# เอกสารความต้องการ (Requirements Document)

## บทนำ

ระบบจัดการแผนกและพนักงานเป็นส่วนหนึ่งของระบบ Project Management ที่ต้องการหน้า UI สำหรับให้ผู้ใช้งานสามารถดู เพิ่ม แก้ไข และลบข้อมูลแผนก (Departments) และพนักงาน (Employees) ได้อย่างสะดวก โดยระบบมี backend API พร้อมใช้งานแล้ว และต้องการพัฒนาส่วน frontend UI ที่เชื่อมต่อกับ API เหล่านี้

ระบบจะต้องรองรับการจัดการสิทธิ์การเข้าถึงตาม policies ที่กำหนดไว้ และมีการแสดงผลข้อมูลแบบ pagination พร้อมฟีเจอร์การค้นหาและกรองข้อมูล

## ความต้องการ

### ความต้องการที่ 1: หน้าจัดการแผนก

**User Story:** ในฐานะผู้ดูแลระบบหรือผู้จัดการ ฉันต้องการดูและจัดการแผนก เพื่อที่จะสามารถจัดระเบียบพนักงานเข้าสู่แผนกที่เหมาะสม

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้เข้าสู่หน้าแผนก ระบบต้องแสดงรายการแผนกทั้งหมดพร้อม pagination
2. เมื่อผู้ใช้มีสิทธิ์ CanViewMasterData ระบบต้องอนุญาตให้ดูรายการแผนก
3. เมื่อผู้ใช้มีสิทธิ์ CanManageMasterData ระบบต้องแสดงปุ่มสร้าง แก้ไข และลบ
4. เมื่อผู้ใช้คลิกปุ่มสร้างแผนก ระบบต้องแสดงฟอร์มที่มีฟิลด์: ชื่อแผนก และสถานะการใช้งาน
5. เมื่อผู้ใช้ส่งข้อมูลแผนกที่ถูกต้อง ระบบต้องเรียก CreateDepartment API และรีเฟรชรายการ
6. เมื่อผู้ใช้คลิกปุ่มแก้ไขแผนก ระบบต้องแสดงฟอร์มที่มีข้อมูลแผนกเดิมอยู่แล้ว
7. เมื่อผู้ใช้ส่งข้อมูลแผนกที่แก้ไข ระบบต้องเรียก UpdateDepartment API และรีเฟรชรายการ
8. เมื่อผู้ใช้คลิกปุ่มลบ ระบบต้องแสดงกล่องยืนยันก่อนเรียก DeleteDepartment API
9. เมื่อการเรียก API ล้มเหลว ระบบต้องแสดงข้อความแจ้งข้อผิดพลาดที่เหมาะสม
10. เมื่อแสดงรายการแผนก ระบบต้องแสดงชื่อแผนก สถานะการใช้งาน วันที่สร้าง และปุ่มจัดการ

### ความต้องการที่ 2: หน้าจัดการพนักงาน

**User Story:** ในฐานะผู้ดูแลระบบหรือผู้จัดการ ฉันต้องการดูและจัดการข้อมูลพนักงาน เพื่อที่จะสามารถรักษาข้อมูลพนักงานและการจัดแผนกให้ถูกต้อง

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้เข้าสู่หน้าพนักงาน ระบบต้องแสดงรายการพนักงานทั้งหมดพร้อม pagination
2. เมื่อผู้ใช้มีสิทธิ์ CanViewDepartmentData ระบบต้องอนุญาตให้ดูรายการพนักงาน
3. เมื่อผู้ใช้มีสิทธิ์ CanManageMasterData ระบบต้องแสดงปุ่มสร้าง แก้ไข และลบ
4. เมื่อผู้ใช้คลิกปุ่มสร้างพนักงาน ระบบต้องแสดงฟอร์มที่มีฟิลด์: UserId, คำนำหน้า, ชื่อ, นามสกุล, อีเมล, ตำแหน่ง, เบอร์โทร, รูปโปรไฟล์, สถานะ, แผนก, การแจ้งเตือน, บทบาท และกลุ่ม
5. เมื่อผู้ใช้ส่งข้อมูลพนักงานที่ถูกต้อง ระบบต้องเรียก CreateEmployee API และรีเฟรชรายการ
6. เมื่อผู้ใช้คลิกปุ่มแก้ไขพนักงาน ระบบต้องแสดงฟอร์มที่มีข้อมูลพนักงานเดิมอยู่แล้ว
7. เมื่อผู้ใช้ส่งข้อมูลพนักงานที่แก้ไข ระบบต้องเรียก UpdateEmployee API และรีเฟรชรายการ
8. เมื่อผู้ใช้คลิกปุ่มลบ ระบบต้องแสดงกล่องยืนยันก่อนเรียก DeleteEmployee API
9. เมื่อแสดงรายการพนักงาน ระบบต้องแสดงชื่อพนักงาน อีเมล ตำแหน่ง แผนก สถานะ และปุ่มจัดการ
10. เมื่อการเรียก API ล้มเหลว ระบบต้องแสดงข้อความแจ้งข้อผิดพลาดที่เหมาะสม

### ความต้องการที่ 3: ฟังก์ชันค้นหาและกรองข้อมูล

**User Story:** ในฐานะผู้ใช้ ฉันต้องการค้นหาและกรองแผนกและพนักงาน เพื่อที่จะสามารถหาข้อมูลที่ต้องการได้อย่างรวดเร็ว

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้พิมพ์ในช่องค้นหาที่หน้าแผนก ระบบต้องกรองแผนกตามชื่อแบบ real-time
2. เมื่อผู้ใช้พิมพ์ในช่องค้นหาที่หน้าพนักงาน ระบบต้องกรองพนักงานตามชื่อ อีเมล หรือตำแหน่งแบบ real-time
3. เมื่อผู้ใช้เลือกกรองแผนกที่หน้าพนักงาน ระบบต้องแสดงเฉพาะพนักงานจากแผนกที่เลือก
4. เมื่อผู้ใช้เลือกกรองสถานะ ระบบต้องแสดงเฉพาะข้อมูลที่ใช้งานหรือไม่ใช้งานตามที่เลือก
5. เมื่อผู้ใช้ล้างตัวกรอง ระบบต้องแสดงข้อมูลทั้งหมดอีกครั้ง

### ความต้องการที่ 4: การเลือกแผนกในฟอร์มพนักงาน

**User Story:** ในฐานะผู้ดูแลระบบ ฉันต้องการกำหนดพนักงานเข้าสู่แผนก เพื่อที่พนักงานจะได้ถูกจัดระเบียบอย่างเหมาะสม

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้เปิดฟอร์มสร้าง/แก้ไขพนักงาน ระบบต้องแสดง dropdown รายการแผนกที่ใช้งานทั้งหมด
2. เมื่อผู้ใช้เลือกแผนก ระบบต้องบันทึก DepartmentId พร้อมกับข้อมูลพนักงาน
3. เมื่อแสดง dropdown แผนก ระบบต้องแสดงชื่อแผนกเรียงตามตัวอักษร
4. ถ้าไม่มีแผนก ระบบต้องแสดงข้อความ "กรุณาสร้างแผนกก่อน"

### ความต้องการที่ 5: การออกแบบแบบ Responsive และประสบการณ์ผู้ใช้

**User Story:** ในฐานะผู้ใช้ ฉันต้องการให้หน้าจัดการแผนกและพนักงานแสดงผลได้ดีและใช้งานง่าย เพื่อที่จะสามารถใช้งานได้บนทุกอุปกรณ์

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้เข้าถึงหน้าบนมือถือ ระบบต้องแสดง layout แบบ responsive พร้อมปุ่มควบคุมที่เหมาะสม
2. เมื่อผู้ใช้เข้าถึงหน้าบนแท็บเล็ต ระบบต้องแสดง layout ที่เหมาะสมสำหรับหน้าจอขนาดกลาง
3. เมื่อผู้ใช้เข้าถึงหน้าบนเดสก์ท็อป ระบบต้องแสดง layout แบบเต็มรูปแบบพร้อมคอลัมน์ทั้งหมด
4. เมื่อแสดงฟอร์ม ระบบต้องแสดง label และข้อความ validation ที่ชัดเจน
5. เมื่อผู้ใช้ส่งฟอร์มที่มีข้อมูลไม่ถูกต้อง ระบบต้องแสดงข้อผิดพลาดแบบ field-level
6. เมื่อกำลังโหลดข้อมูล ระบบต้องแสดง loading indicator
7. เมื่อการทำงานสำเร็จ ระบบต้องแสดงการแจ้งเตือนความสำเร็จ

### ความต้องการที่ 6: การนำทางและ Routing

**User Story:** ในฐานะผู้ใช้ ฉันต้องการนำทางระหว่างหน้าจัดการแผนกและพนักงานได้ง่าย เพื่อที่จะสามารถจัดการทั้งสองส่วนได้อย่างมีประสิทธิภาพ

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้อยู่ที่หน้าแผนก ระบบต้องมีลิงก์นำทางไปหน้าพนักงาน
2. เมื่อผู้ใช้อยู่ที่หน้าพนักงาน ระบบต้องมีลิงก์นำทางไปหน้าแผนก
3. เมื่อผู้ใช้คลิกชื่อแผนกในรายการพนักงาน ระบบต้องนำทางไปหน้าแผนกพร้อม highlight แผนกนั้น
4. เมื่อผู้ใช้นำทางด้วยปุ่ม back ของเบราว์เซอร์ ระบบต้องรักษาสถานะหน้าไว้อย่างถูกต้อง
5. เมื่อผู้ใช้ที่ไม่มีสิทธิ์พยายามเข้าถึงหน้า ระบบต้อง redirect ไปหน้า login หรือ not-authorized

### ความต้องการที่ 7: การตรวจสอบข้อมูล

**User Story:** ในฐานะผู้ดูแลระบบ ฉันต้องการให้ระบบตรวจสอบข้อมูลที่ป้อน เพื่อที่จะมีเฉพาะข้อมูลที่ถูกต้องถูกส่งไปยัง backend

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้ส่งฟอร์มแผนก ระบบต้องตรวจสอบว่าชื่อแผนกเป็นฟิลด์บังคับและไม่ว่างเปล่า
2. เมื่อผู้ใช้ส่งฟอร์มพนักงาน ระบบต้องตรวจสอบว่า UserId, อีเมล, ชื่อ และนามสกุลเป็นฟิลด์บังคับ
3. เมื่อผู้ใช้ป้อนอีเมล ระบบต้องตรวจสอบรูปแบบอีเมล
4. เมื่อผู้ใช้ป้อนเบอร์โทร ระบบต้องตรวจสอบรูปแบบเบอร์โทร (ถ้ามีการป้อน)
5. ถ้าการตรวจสอบล้มเหลว ระบบต้องป้องกันการส่งฟอร์มและแสดงข้อความแจ้งข้อผิดพลาด
6. เมื่อการตรวจสอบผ่านทั้งหมด ระบบต้องเปิดใช้งานปุ่มส่งข้อมูล

### ความต้องการที่ 8: การจัดการรูปโปรไฟล์

**User Story:** ในฐานะผู้ดูแลระบบ ฉันต้องการอัพโหลดและแสดงรูปโปรไฟล์พนักงาน เพื่อที่พนักงานจะสามารถถูกระบุได้ง่าย

#### เกณฑ์การยอมรับ

1. เมื่อผู้ใช้เปิดฟอร์มพนักงาน ระบบต้องแสดงฟิลด์อัพโหลดรูปภาพ
2. เมื่อผู้ใช้เลือกไฟล์รูปภาพ ระบบต้องตรวจสอบประเภทไฟล์ (jpg, png, gif)
3. เมื่อผู้ใช้เลือกไฟล์รูปภาพ ระบบต้องตรวจสอบขนาดไฟล์ (สูงสุด 5MB)
4. เมื่อเลือกรูปภาพที่ถูกต้อง ระบบต้องแสดงตัวอย่างรูปภาพ
5. เมื่อพนักงานมีรูปโปรไฟล์ ระบบต้องแสดงรูปขนาดย่อในรายการพนักงาน
6. ถ้าพนักงานไม่มีรูปโปรไฟล์ ระบบต้องแสดงรูป avatar เริ่มต้น
7. เมื่อผู้ใช้ส่งฟอร์มพร้อมรูปภาพ ระบบต้องอัพโหลดรูปภาพและบันทึก URL ของ ImageProfile
